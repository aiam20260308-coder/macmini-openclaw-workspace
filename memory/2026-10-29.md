## Mac mini Sidecar Setup (Completed 2026-10-27, verified 2026-10-29)

> [project: /Users/alexlam/.openclaw/workspace]

**Goal:** Enable iPad as main display on headless Mac mini (no HDMI).

### Architecture
```
Mac mini (no HDMI)
  └── Crisp → Creates virtual display (HiDPI, 4:3 ratio)
        └── macOS recognizes virtual display → Allows Sidecar
              └── sidecar-connect → Connects iPad as Sidecar display
```

### Installed Tools (persist across reboots)
- `~/.local/bin/sidecar-connect` (v0.2.0) — Control Sidecar connections
- `~/.local/bin/crispctl` — CLI for Crisp (from Crisp v1.7.1)
- `/Applications/Crisp.app` — Create/manage virtual displays
- `/Applications/RustDesk.app` — Remote desktop (server mode, port 21118/21119)
- Docker container `searxng` (port 8080) — Web search engine

### Removed (2026-10-27)
- BetterDisplay completely removed (app, preferences, app support, CLI wrapper `bdisplay`)

### Workflow
1. Ensure Crisp creates virtual display (manually via Crisp UI)
2. Run: `~/.local/bin/sidecar-connect connect`
3. Verify: `~/.local/bin/sidecar-connect status --json`
4. Check displays: `system_profiler SPDisplaysDataType 2>&1 | grep -A25 "Displays:"`

### Troubleshooting
- **Sidecar disconnects:** iPad locked or out of range → reconnect with `sidecar-connect connect`
- **BetterDisplay replacement:** Crisp's virtual display persists when iPad disconnects (BetterDisplay's vanished)
- **Crisp custom resolution:** Free (BetterDisplay required Pro tier)
- **RustDesk restart:** `open /Applications/RustDesk.app` (already in Login Items)

### Quick Commands
| Command | Purpose |
|---------|---------|
| `sidecar-connect connect` | Connect iPad |
| `sidecar-connect disconnect` | Disconnect iPad |
| `sidecar-connect status --json` | Check connection |
| `sidecar-connect toggle` | Connect/disconnect toggle |
| `crispctl display list` | List Crisp-managed displays |

## web_search Fix (2026-10-28)

> [project: /Users/alexlam/.openclaw/workspace]

**Problem:** `web_search` tool returned "not found" repeatedly.

**Root Cause:** Empty `"openaiCodex": {}` in `tools.web.search` broke tool registration.

**Fix:** Removed `"openaiCodex": {}` from `openclaw.json`.

**Before (broken):**
```json
"web": {
  "search": {
    "provider": "searxng",
    "enabled": true,
    "openaiCodex": {}
  }
}
```

**After (fixed):**
```json
"web": {
  "search": {
    "provider": "searxng",
    "enabled": true
  }
}
```

**Verification:** Source code (`codex-native-web-search.shared.ts`) reads `config?.tools?.web?.search?.openaiCodex`. Empty object fails all validation checks → `resolveCodexNativeWebSearchConfig()` returns `{ enabled: false, ... }`.

**Note:** `openaiCodex` is a valid config key for "Codex native web search" (mode, allowedDomains, userLocation). Empty object only makes sense if you actually use this feature. For SearXNG users, just remove it.
